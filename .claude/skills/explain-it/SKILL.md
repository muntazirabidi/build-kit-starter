name: explain-it
description: Explain the project or a recent change in plain English for a non-programmer. Use when the user asks what something does, how it works, or "what did you just do".
---
Explain $ARGUMENTS (or, if empty, the last change you made) for someone who has never coded.

1. One sentence: what it does for the user.
2. A short walk through what happens, step by step, like a recipe. Name files only if they help.
3. One thing that could go wrong and how we would notice.
No jargon. If you must use a technical word, explain it in brackets.
